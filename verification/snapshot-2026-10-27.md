## Not verified

| Item | Reason |
|---|---|
| GPU memory total and free, PCIe topology, CUDA peer-access result | The recording shell ran with a minimal `/dev` and no `/dev/nvidia*` nodes, so `nvidia-smi` reported "couldn't communicate with the NVIDIA driver" and `llama-cli --list-devices` failed to initialise CUDA. This is a limitation of that shell, not evidence of a fault: the driver module is loaded, `/proc/driver/nvidia/version` resolves, and both cards are present on the PCI bus. VRAM figures in the README are the 16 GB capacity of each card; per-device UUIDs are redacted in this public copy. |
| Weight SHA-256 values | Not recomputed for this snapshot (about 34 GB of reads). Values in `models/manifest.json` are those recorded at download time on 27 September 2026. |
| ComfyUI weight presence and sizes | The stack was stopped; its manifest was read, not re-checked against disk. |
| MTP and KV-context qualification status | Reported from `config/profiles.json`. No inference was run, so no behavioural re-test was performed. |
| Throughput or latency figures | Out of scope for this snapshot; no benchmarks were run. |

## Sanitisation applied to this public copy

- Absolute home-directory paths were removed from the published configuration
  and reserved-source entries; evidence pointers that referenced local files are
  omitted rather than rewritten.
- GPU UUIDs are replaced with `GPU-SLOT-0` and `GPU-SLOT-1`, including where they
  appear as keys in the KV-context experiment policy.
- Container image manifest digests are omitted. The deployment pins both images
  by digest; this copy records versions and registry tags only.
- No logs, backups, runtime state, model weights, or benchmark artefacts are
  included.
